# 3. Go live on your domain

Outside localhost, PostKing only serves a self-hosted page to a domain you've
proven you own.

## Add the domain as self-hosted

1. In [PostKing](https://postking.app), open **Settings → Domains → Add
   domain**.
2. Enter your domain and choose **Self-hosted** ("I serve it myself").
3. Add the TXT record PostKing shows you at your DNS provider:

   | Type | Name | Value |
   |---|---|---|
   | TXT | `_postking-verify` | `postking-verify-…` (copy it from the dashboard) |

   No A record — your own server serves the domain, not PostKing.
4. Click **Verify**. DNS can take a few minutes to propagate.

CLI equivalent:

```bash
pking domains add example.com --hosting-mode self_hosted
pking domains verify example.com
```

## Connect it to the page

Back on the page's **Distribution** screen, pick the verified domain under
**Production domain** and connect it. Or:

```bash
pking lp connect-domain my-page --domain-id <domain-id>
```

A domain's mode must match the page's distribution: a self-hosted domain only
connects to a Self-hosted page, and vice versa. To switch, disconnect the
domain first.

## Deploy

Deploy this app anywhere that runs Node (Vercel, Fly, Render, a VPS):

1. Set the same env vars on the host, with `SITE_URL` set to your real domain,
   e.g. `https://example.com`.
2. Build with `pnpm build`, run with `pnpm start`. The build fetches from
   `POSTKING_API_URL`, so the build machine needs network access to it.
3. Point your domain's DNS at your host.

Pages refresh from PostKing every 5 minutes (ISR), so edits you publish show up
without a redeploy.

## Social share images

The default share image (`/api/uploads/og-images/<slug>.png`) is generated by
PostKing after the domain is verified. Until then, shared links may show no
image.
