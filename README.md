# postking-selfhost

A minimal, public-domain (Unlicense OR MIT-0) **reference implementation** of a self-hosted
renderer for your PostKing landing page, side pages, and blog — one example
of calling PostKing's public API yourself, not the required way to do it.
Feel free to build your own against the same endpoints (`GET
/api/landing-pages/{slug}`, `GET /api/blog-posts`, `GET
/api/blog-posts/{articleSlug}`) in any stack you like.

This renderer itself is bare-bones and single-tenant: it renders your
content as plain semantic HTML, with a small layer of minimal, unbranded
layout CSS (`app/globals.css`) — no design system, no CSS framework, no
brand colors. It's meant to be restyled: fork it and make it look like your
brand.


Full guide — creating a page on [PostKing](https://postking.app), self-hosting it, going live, and the API: see [`docs/`](docs/README.md). See [Known limitations](docs/05-customize.md#known-limitations) for what this starter deliberately doesn't render.

## Quickstart

```
git clone https://github.com/bitsandtea/postking-selfhost.git
cd postking-selfhost
cp .env.example .env
pnpm install
pnpm dev
```

Then open `http://localhost:3000`.

### Local https

`pnpm dev:https` serves `https://localhost:3001` with a locally generated
certificate — set `SITE_URL=https://localhost:3001` to match. Both dev scripts
also trust your local mkcert certificate authority, so an https API origin
signed by it works too.

## Configuring your brand

Edit `.env`:

- `POSTKING_API_URL` — your PostKing account's origin, e.g. `https://try.postking.app`.
- `POSTKING_BRAND_SLUG` — your landing page's slug. Find it in the PostKing
  dashboard: Landing Pages → your page → the slug shown in its URL
  (`/dashboard/brands/<brandId>/landing-pages/<slug>`).
- `SITE_URL` — the public URL this site will be served at once deployed
  (drives the sitemap, canonical URLs, and robots.txt).
- `POSTKING_IMAGE_BASE_URL` (optional) — only set this if PostKing told you
  to serve assets from a separate CDN origin; defaults to `POSTKING_API_URL`.

## Routes

- `/` — your landing page
- `/[page]` — a side page (comparison, custom, etc.) by its slug
- `/blog` — blog index
- `/blog/[slug]` — a blog article
- `/blog/category/[slug]` — a blog category hub (only appears once a
  publication has enough categorized articles for PostKing to expose them)
- `/tools/[slug]` — a published Tool's copy plus its input form. The form is
  the starter's only client component; it posts to this site's own
  `/api/tools/[slug]/execute`, which proxies to PostKing (same origin, so no
  CORS; no auth added). Async tools aren't supported yet.
- `/sitemap.xml`, `/robots.txt`, `/llms.txt`, `/favicon.ico` — generated from
  the same API data.

## A note on production custom domains

PostKing's landing-page API only serves content to its own preview domain,
to `localhost`/`127.0.0.1` for a page set to **Self-hosted** under
Distribution, or to a domain that's been **verified as this landing page's
custom domain**. Every other host gets a 403.

1. In the PostKing dashboard, open this page's Distribution modal and choose
   **Self-hosted**. Once the page is published, `pnpm dev` against
   `POSTKING_API_URL=https://try.postking.app` works immediately — no domain
   needed yet.
2. When you're ready to deploy to `SITE_URL` in production, add that domain
   as **self-hosted** in Domain Settings (verification only checks a TXT
   ownership record — there's no A record, since your own server serves it,
   not PostKing's), then connect it to this page from the Distribution
   modal.

Social share images: the fallback OG image
(`{POSTKING_API_URL}/api/uploads/og-images/{slug}.png`) is only generated by
PostKing after the domain is verified and its background job has run, so
share cards may show no image until then.

## Deploying

Any Node host or Vercel. Build with `pnpm build`, run with `pnpm start`, and
set the same env vars from `.env` on the host. The build fetches from
`POSTKING_API_URL` to prerender pages, so the build environment needs
network access to it.
